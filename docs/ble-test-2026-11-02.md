# BLE 板级验收测试（N32-NimBLE）

验证日期：2026-11-02（Asia/Shanghai，命令行输出为 UTC）。只做空中（OTA）黑盒验收：不烧录、不使用 probe-rs/GDB/RTT、不改动固件与工具。

## 结论（最终）

- **已验证**：广播（Mac + 安卓双端）、连接、GATT 服务/特征发现（NUS + 测试服务 `7a02480e-…e01` 的 3 个特征齐全）、echo 写读回校验（Mac 8 字节、安卓 4 字节均一致）、uptime 秒计数递增且与墙钟同步、跨平台读数一致、主动断链与断链后重新广播。
- **预期失败（能力上限，非缺陷）**：PHY 切换。闭源 NZ8801 controller 不实现 LE Read PHY / LE Set PHY HCI 命令（返回 HCI status 0x01 Unknown Command），任何 PHY 请求都无法完成。固件 `…3e04` 已优雅降级：写不再报 ATT 错误、读回 6 字节状态、status 字节如实上报 0x01。客户端按"请求的 PHY 未被选中"判 fail（Mac exit 5、安卓 exit 6）——预期失败：闭源 controller 不支持 LE PHY HCI 命令，status=0x01。
- **未测（超出本轮范围）**：`perf.py`、`reliability.py`、`--perf`、`--echo-perf`、`l2cap` 子命令（依赖本固件未实现的 `…3e05/…3e06` 特征与 PSM 128，且耗时长）；NUS notify 数据通路、配对/绑定、吞吐量。

## 问题定位与修复复测（20:39 固件更新后）

首轮暴露的两个问题当日定位修复并重新烧录（广播名与地址不变），复测于 UTC 12:42–12:45（本地 20:42–20:45）完成，约束不变：不动 tools/、不动过滤器、不烧录、每条命令最多重试一次（本轮无失败重试）。

### 1. uptime 恒为 0 → 已修复，pass

**根因**：`FreeRTOSConfig.h` 自定义了 `configSYSTICK_CLOCK_HZ`。ARM_CM4F port 在该宏存在时选择"SysTick 外部参考时钟"并清除 CLKSOURCE 位；该参考时钟在 N32WB452 上没有运行，SysTick 冻结（板上实测 `CTRL=0x3`、`VAL=0`、`xTickCount` 恒 0）。所有 `vTaskDelay`、软件定时器与 NimBLE callout 全部瘫痪，BLE 靠纯事件驱动侥幸工作——这正是首轮连接、发现、echo 都正常而 uptime 为 0 的原因。

**修复**：删除该宏定义，port 自选内核时钟作为 SysTick 源。

**复测数据**（uptime 读值，除注明外均为 Mac `probe`）：

| 读取时刻（UTC） | 读数 | 说明 |
| --- | --- | --- |
| 12:42:34 | `b4000000` = 180 s | 修复后首次读，非零 |
| 12:43:16 | `dd000000` = 221 s | 与上次读墙钟间隔 42 s，读数 +41 s，1 s 内一致 |
| 12:43:25 | `e6000000` = 230 s | M4 附带读，221+9 与墙钟吻合 |
| 12:44:24（安卓 A4） | `20010000` = 288 s | 距 Mac 的 230 s 读数墙钟 +59 s、读数 +58 s，跨平台一致 |

**判定**：uptime 用例（M3/A4）最终 **pass**。uptime 由 FreeRTOS tick 驱动，其正常递增同时证明 vTaskDelay/软件定时器/callout 路径已恢复。

### 2. PHY 特征 ATT 0x0E → 优雅降级落地，PHY 切换为预期失败

**根因**：闭源 NZ8801 controller 不实现 LE Read PHY / LE Set PHY HCI 命令，返回 HCI status 0x01（Unknown Command）。修复前固件把该失败原样上抛为 ATT 错误 0x0E（Unlikely Error），导致 `…3e04` 连读都失败，也因此无法从空中区分"仅 2M 不支持"与"整个 PHY 通路不可用"。

**修复**：`…3e04` 优雅降级——读不再报 ATT 错误，回退报告 LE 默认 1M；写不再报 ATT 错误，把真实 HCI 错误码放入 6 字节状态的 status 字节。

**复测输出**：

Mac（`probe --phy 2m --write-hex '00 ff 80 7f' --timeout 40`，exit 5，`reason=phy_not_selected`，`failures=0`）：

```text
{"event":"write","hex":"02","uuid":"...3E04"}                        # 写成功，无 ATT 错误
{"event":"phy_status","operation":"wait_phy","tx_phy":1,"rx_phy":1,
 "pending":false,"status":1,"requested_mask":2}                      # status=1=HCI Unknown Command，仍 1M/1M
{"event":"summary","reason":"phy_not_selected","exit_code":5,"failures":0,...}
```

安卓（`gatt --uuid …3e04 --write-hex 02`，exit 6）：写后成功读回 6 字节 `010101000102` =
`[ver=1, tx=1(1M), rx=1(1M), pending=0, status=1(HCI 0x01), requested=2(2M)]`；
本步 logcat 不再出现 `received: 14`（修复前为 `onCharacteristicWrite/Read received: 14`，工具 exit 2 "Hex characteristic value not present after read"）。

**判定**：M5/A6 更新为 **fail（预期失败：闭源 controller 不支持 LE PHY HCI 命令，status=0x01）**。失败模式从"协议错误（ATT 0x0E，连状态都读不到）"变为"数据面如实上报（写成功 + 6 字节状态 + status 字节报真实 HCI 错误码）"，降级行为按设计验证；客户端因 `status≠0` 判 fail 属预期。

## 异常与观察

1. **（修复前，已定位）PHY 特征 `…3e04` 读写全被拒**。首轮两台主机、三次连接（Mac 2M ×2、Mac 1M ×1、安卓 2M ×1）结果一致：写返回 ATT 错误 0x0E，安卓侧随后读也返回 0x0E，UI 上该特征始终无值。CoreBluetooth 的 `"Unlikely error."` 与安卓 status 14 精确对应，证明是固件/控制器返回的 ATT 错误而非主机实现差异；当时因 1M 与 2M 同样被拒，只能推测 `…3e04` 访问回调整体失败。后经固件侧确认根因为 NZ8801 不实现 LE PHY HCI 命令（0x01）且固件未降级，已修复，见"问题定位与修复复测"第 2 节。
2. **（修复前，已定位）uptime 恒为 0**。UTC 12:20:59（Mac）、12:21:19（Mac，间隔 20 s）、12:25:06Z（安卓，再隔约 4 分钟）三次连接读出均为 `00000000`，且当时因 duration 模式依赖 set_phy 失败而无法在连接内观察。根因为 `configSYSTICK_CLOCK_HZ` 宏导致 SysTick 选了未运行的外部参考时钟，已删除该宏修复，复测递增正常，见第 1 节。
3. **（复测新增）修复后失败模式变化是判定 PHY 用例的关键证据**：M5 的 summary 里 `failures=0`（首轮为 1）——客户端不再把 PHY 流程记为协议失败，只按"请求未选中"结束；`…3e04` 的读值从"不存在"变为 6 字节状态，status 字节=0x01 与根因吻合，双平台一致。
3. **RSSI 与广播质量**。Mac −59…−71 dBm，安卓 −48…−52 dBm；安卓 HCI 显示广播间隔 33 ms，主广播与 scan response 成对出现（540/535），`kCBAdvDataIsConnectable=1`。广播与扫描响应链路健康。
4. **手机过滤器未构成阻碍**。nRF 过滤器 `nimble, -75 dBm` 对 `N32-NimBLE`（含子串匹配通过）且目标 RSSI 优于阈值，全程 `filters_preserved=true`。
5. **客户端行为**。probe 结束后的 2 秒收尾按文档预留，probe 间 `sleep 3`，连续连接无异常；Mac 端未出现名称缓存问题（每次都按名称直接匹配到同一 identifier）。

## 未测项（及原因）

- `perf.py`、`reliability.py`、`--perf`、`--echo-perf`、`l2cap` 子命令：超出本轮范围。本固件仅实现 NUS 与 `…3e01` 测试服务，无 `…3e05/…3e06` 与 PSM 128，且这些用例耗时长。
- NUS notify 数据通路（`6E400003`）：本轮命令集不含订阅通知的用例，未覆盖。
- 配对/绑定、加密：无此轮用例；两平台连接均为未加密 GATT 访问。
- 吞吐量/丢包率：依赖上述未测工具。
- Coded PHY（`03/04`）：Mac 客户端不接受 coded 参数；且 controller 不实现 LE PHY HCI 命令，任何 PHY（含 coded）请求都会以 status=0x01 失败，无需再测。
